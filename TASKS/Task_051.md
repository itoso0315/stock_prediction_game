

# Task 051: 予測期間を「過去120営業日 → 1か月後」に変更し、Result判定表示を改善する

## 目的
ゲームの予測ルールを、現在の「過去60営業日を見て約3か月後を予測」から、「過去120営業日（約半年）を見て約1か月後を予測」へ変更する。

あわせてResult画面の正解・不正解表示を視覚的に分かりやすくし、正解時は緑、不正解時は赤で結果を認識できるようにする。

## 変更後のゲームルール

- 問題画面で表示する期間：基準日までの直近120営業日（約半年）
- 予測対象期間：基準日から約1か月後まで
- Chart A / B / Cは同一Question内で同じ基準日・評価日を使用する
- 基準日から評価日までの騰落率を比較する
- 現金保有は0.0%として比較する
- A/B/C/現金保有のうち最も騰落率が高い選択肢を正解とする

## 実装内容

### 1. 問題チャートを120営業日に変更する
- Chart A / B / Cすべてについて、問題画面に表示するOHLCを60営業日から120営業日へ変更する。
- Volumeも同じ120営業日に揃える。
- candlesは日付昇順とする。
- 基準日は120営業日の最終日とする。
- 基準日より未来のOHLC / Volumeを問題画面へ含めない。
- 銘柄名・ticker等の答えにつながる情報を問題画面へ表示しない現在の仕様を維持する。

### 2. MA20 / MA40 / MA70を120営業日表示へ対応させる
- MA20 / MA40 / MA70の既存ON/OFF機能を維持する。
- MA計算に必要な120営業日以前の株価データを取得してよい。
- 表示開始直後から可能な限り正しいMAを描画する。
- MA計算に基準日より未来のデータを使用しない。
- カード外の共通「移動平均線 ON／OFF」で、A/B/CのMA20 / MA40 / MA70を一括表示する現在の仕様を維持する。

### 3. 評価日を「約1か月後」に変更する
- 現在の約3か月後という評価期間を廃止する。
- 評価日は基準日から約1か月後とする。
- 1か月後の日付が休日・休場日の場合は、既存方針に沿って実際に評価可能な適切な取引日を使用する。
- Question画面に表示する評価日と、Backendで騰落率計算に使用する評価日を必ず一致させる。
- A/B/Cは同じ評価日を使用する。

### 4. Question画面の問題文を新ルールへ合わせる
Question画面には基準日と評価日を表示し、120営業日を見て約1か月後を予測するゲームであることが分かる文言にする。

表示イメージ：

```text
基準日：2024/05/01
評価日：2024/06/03

過去約半年のチャートを見て、
評価日までに最も上昇すると思うものを選んでください。
```

- 実際に使用する基準日・評価日を表示する。
- 「3か月後」等の旧仕様の文言を残さない。
- 問題文を増やしすぎず、チャートを主役にする。

### 5. Result用チャートを「過去120営業日＋未来約1か月」に変更する
Chart A / B / CのResultチャートを以下の構成へ変更する。

```text
問題時に見えていた過去120営業日       予測対象だった約1か月

────────────────────│──────────
                    ↑
                 予測基準日
```

- 左側はQuestion画面で実際に表示した120営業日。
- 右側は基準日より後、評価日までの実際の株価。
- 過去と未来を一本の連続したチャートとして表示する。
- 予測基準日の境界は、実線ではなく縦の点線で表示する。
- 予測基準日を示す縦の点線は、ローソク足や出来高を邪魔しない視認性にする。
- 予測基準日より左側、つまりQuestion画面でユーザーが実際に見ていた過去120営業日のチャート領域には、薄い灰色の背景色を付ける。
- 基準日より右側の未来約1か月の領域は、過去領域との違いが一目で分かるよう、薄い灰色の背景を付けない。
- 灰色背景はローソク足・MA・出来高の視認性を損なわない程度の薄さとし、既存のダークUIに自然に馴染ませる。
- 「薄い灰色の過去領域 → 縦の点線による予測時点 → 背景色のない未来領域」という視覚構造で、どこまでを見て予測したのか直感的に理解できるようにする。
- 出来高も同期間で表示する。
- Question画面に未来データを漏らさない。

視覚表現のイメージ：

```text
┌──────────────────────────────┐
│ 薄い灰色の背景      ┊ 未来     │
│ 過去120営業日       ┊ 約1か月   │
│ ローソク足          ┊ ローソク足│
│                    ┊          │
│                    ┊          │
│                    ↑          │
│                 予測時点       │
└──────────────────────────────┘
                       ↑
                    縦の点線
```

### 6. 騰落率を1か月後基準で再計算する
- Chart A / B / Cそれぞれについて、基準日終値から評価日終値までの騰落率を計算する。
- Result画面に表示する騰落率と正解判定に使用する騰落率を一致させる。
- 現金保有は0.0%。
- 旧3か月評価の固定値・ダミー値・文言を残さない。

### 7. 正解・不正解の文字色を変更する
Result画面の最上部など、ユーザーが回答結果を最初に認識する場所に表示する「正解」「不正解」の文字を以下の色で表示する。

- 正解：緑
- 不正解：赤

要件：
- 正解の場合は「正解」の文字自体を緑で表示する。
- 不正解の場合は「不正解」の文字自体を赤で表示する。
- 既存のダークUI上で十分な視認性を確保する。
- 色だけに依存せず、「正解」「不正解」という文字も必ず表示する。
- 正解カードやユーザー選択カードの既存表示と矛盾しないようにする。
- UI全体を緑や赤に染めるのではなく、結果を認識するためのアクセントとして使用する。

表示イメージ：

```text
正解        ← 緑文字
```

または

```text
不正解      ← 赤文字
```

### 8. 既存の結果比較仕様を維持する
Result画面では引き続き以下を表示する。

- Chart A / B / C
- 現金保有 0.0%
- 各Chartの実際の騰落率
- ユーザーが選択した回答
- 実データから決定した正解
- 銘柄名 / ticker等の答え合わせ情報
- 基準日 / 評価日
