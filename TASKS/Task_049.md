

# Task 049: 完成した実データチャートをChart B / Cへ横展開する

## 目的
Task046〜048でChart Aに実装した実データチャート機能をChart B / Chart Cにも展開し、3つの実在銘柄の過去チャートを比較して投資先を選べる問題画面を完成させる。

Chart A / B / Cは同一の基準日を使用し、それぞれ別の実在日本株を表示する。
問題画面では銘柄名・tickerを隠し、チャート情報だけで判断する現在のゲームコンセプトを維持する。

## 現在地
- FlutterとFastAPIの連携は完了している。
- Chart Aはyfinanceから取得した実在日本株のデータを使用している。
- Chart Aには基準日までの過去60営業日のローソク足を表示できる。
- Chart Aには同期間の実際の出来高を表示できる。
- カード外の共通ボタンでMA20 / MA40 / MA70を一括ON/OFFできる。
- MAの初期状態はOFFで、Questionを移動しても状態を維持する。
- 問題画面には基準日より未来のデータを表示しない。
- Chart B / Cはまだプレースホルダーまたは空データの状態。
- 現金保有は回答候補として残す。
- Result画面はまだダミー中心であり、後続Taskで本物の将来データを使った答え合わせ画面へ刷新する。

## 実装方針
Chart Aで完成・検証済みのチャート仕様を再利用し、Chart B / Cにも同じ機能を持たせる。

Chart B / C専用の重複実装を増やすのではなく、既存の共通モデル・Widget・Backend処理を活用する。
ただしTask049のために不要な大規模リファクタリングは行わない。

このTaskでは問題画面のA/B/Cを本物にすることを主目的とし、Result画面の本物データ化には着手しない。

## 実装内容

### 1. Chart A / B / Cへ別々の実在日本株を割り当てる
- 1問につきChart A / B / Cの3つすべてに実在日本株を割り当てる。
- A/B/Cは互いに異なる銘柄とする。
- 日本株を対象とする。
- 現時点では既存の問題定義に沿った固定tickerでもよい。
- ランダム出題の本格実装は別Taskとしてよい。
- 問題画面には銘柄名・tickerを表示しない。

### 2. A/B/Cで同一の基準日を使用する
- 同じQuestion内のChart A / B / Cは必ず同一の`baseDate`を使用する。
- 各Chartにはその基準日までの過去60営業日を表示する。
- 基準日より未来のOHLC / Volume / MAを問題画面へ含めない。
- yfinanceの休場日等により銘柄間で取得可能日が異なる場合も、比較の公平性を損なわないよう既存データ取得処理を利用して適切に処理する。

### 3. Chart B / Cも実OHLCへ変更する
Chart Aと同じ仕様で以下を表示する。

- 過去60営業日のOpen
- High
- Low
- Close
- 日付昇順

既存のCandlestickChartを再利用する。

### 4. Chart B / Cにも実出来高を表示する
- yfinanceから取得したVolumeを使用する。
- ローソク足と出来高の日付・X座標を一致させる。
- Chart Aと同じ表示比率・描画仕様を使用する。
- Volumeのない既存データに対する互換性を壊さない。

### 5. Chart B / CにもMA20 / MA40 / MA70を対応させる
- Chart Aと同じ計算方式を使用する。
- MA計算に未来データを使用しない。
- 60営業日の表示開始以前のデータを計算に利用してよい。
- カード外の共通「移動平均線表示」ボタンでMA20 / MA40 / MA70を一括ON/OFFできる。
- 初期状態はOFF。
- ON/OFF状態はA/B/Cすべてへ共通で反映する。
- Questionが切り替わってもON/OFF状態を維持する。

### 6. Chart A / B / Cの回答選択を維持する
- Chart A / B / Cそれぞれのカード全体をタップして回答候補として選択できる。
- `Chart A` / `Chart B` / `Chart C`のラベルは必ず残す。
- カード外のMA切替操作によって回答選択が誤作動しないようにする。
- 選択中のカードが現在どれか分かる既存UIを維持する。
- 回答確定ボタンの既存仕様を維持する。

### 7. 現金保有を4つ目の選択肢として維持する
問題画面の回答候補は最終的に以下の4つとする。

```text
Chart A
Chart B
Chart C
現金保有
```

- 現金保有にはチャートを表示しない。
- 現金保有カードの既存UIを維持する。
- 現金保有を選択して回答確定できること。

### 8. Backend処理を3Chartへ展開する
- Task046〜048でChart Aだけに行っていた実データ注入処理をA/B/Cへ展開する。
- 3銘柄すべてについてOHLC / Volume / MAデータを生成する。
- Yahoo Finance取得失敗時は既存のエラー処理方針を維持する。
- 固定ダミーOHLCへ黙ってフォールバックしない。
- APIレスポンス形式は既存Flutterとの互換性を維持する。

### 9. パフォーマンスに配慮する
A/B/Cの3銘柄を取得するため、1問あたりの外部データ取得量が増える。

このTaskでは大規模なキャッシュ機構の実装を必須としないが、以下を守る。

- 同一ticker・同一期間を不必要に複数回取得しない。
- 既存の取得処理を可能な範囲で再利用する。
- 将来キャッシュや問題事前生成へ移行しやすい構造を壊さない。

レスポンス速度が実用上大きな問題になる場合は、必要最小限の改善を行ってよい。

### 10. テストを追加・更新する
少なくとも以下を確認する。

Backend：
- 1問のA/B/Cすべてに実データが入る。
- A/B/Cが別tickerになっている。
- A/B/Cが同一baseDateを使用する。
- 各Chartに60営業日程度のOHLCが入る。
- 各ChartにVolumeが入る。
- 各ChartにMA20 / MA40 / MA70が入る。
- 全データが日付昇順。
- 基準日より未来の問題画面用データが含まれない。
- Chart Aで既に動いている仕様を壊していない。

Flutter：
- A/B/Cすべてにローソク足＋出来高が表示できる。
- 共通ボタンでA/B/CすべてのMAを一括ON/OFFできる。
- MA初期状態はすべてOFF。
- Question切替時にMA状態が維持される。
- A/B/Cカードをそれぞれ回答選択できる。
- 現金保有も選択できる。
- 回答確定からResultまで遷移できる。
