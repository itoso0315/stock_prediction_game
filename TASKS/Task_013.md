# Task 013

## タイトル
問題画面の選択UIと配色を改善する

## 1. 目的

問題画面で、利用者がどのChartを選択しているかを直感的に理解できるようにする。

現在の各チャート下にある選択ボタンを廃止し、各チャート左側に選択UIを置く。あわせて、真っ白で業務画面のように見える問題画面を、カードと配色によってゲームとして触りやすい画面へ改善する。

## 2. 実装方針

Streamlit標準コンポーネントと`app.py`内の必要最小限のCSSだけで実装する。

JavaScriptは追加しない。

Streamlit標準の`st.radio`を3つのカードへ分散配置することはできないため、各カード左側にはラジオボタン風の`st.button()`を配置する。

選択状態は既存の`answer_choice`だけを正とする。

ライトテーマのみを対象とし、ダークモード対応は今回の対象外とする。

## 3. 選択UI

各Chart A/B/Cを1つのカードとして表示する。

カード内部は左右2列とする。

- 左列：ラジオボタン風の選択ボタンとChartラベル
- 右列：既存のPlotlyチャート

選択ボタンとChartラベルは1つの`st.button()`として実装する。

左右列の比率は、Chartラベルが不自然に折り返されず、Plotlyチャートの横幅を損なわない範囲で設定する。

表示文言は次とする。

未選択：

```text
○ Chart A
○ Chart B
○ Chart C
```

選択中：

```text
● Chart A
● Chart B
● Chart C
```

選択中のChartだけ`●`を表示し、それ以外は`○`を表示する。

これにより、選択状態を色だけに依存させない。

## 4. 選択操作

- Chart A、Chart B、Chart Cの選択ボタンをクリックすると、既存の`select_answer()`を`on_click`コールバックとして使用し、`answer_choice`へ対応するChartラベルを保存する。
- 選択状態は常に1つだけとする。
- 回答確定前は何度でも選び直せる。
- 別のChartを選択すると、それまでの選択は解除される。
- カード全体をクリック可能にはしない。
- チャート下の既存選択ボタンは削除する。
- 選択操作では明示的な`st.rerun()`を追加しない。
- Streamlitの通常再実行により、クリック直後に`○`／`●`とカード配色を更新する。
- 選択操作のたびに問題画面用Figure 3件が再生成されることは許容する。
- 選択操作によって`game_question`を再生成しない。

## 5. カードUI

各Chartは`st.container(key=...)`を使用してカード化する。

使用するcontainer keyは次とする。

- `chart_card_a`
- `chart_card_b`
- `chart_card_c`

container keyはCSSによる識別に使用してよい。

### 未選択カード

- 背景色：`#FFFFFF`
- 枠線：`1px solid #D9E2EC`
- 角丸：`12px`
- 内側余白：`12px`
- カード間余白：`16px`
- 影：`0 2px 8px rgba(15, 23, 42, 0.06)`

### 選択中カード

- 背景色：`#F3F8FF`
- 枠線：`2px solid #4A90E2`
- 角丸：`12px`
- 内側余白：`12px`
- カード間余白：`16px`
- 影：`0 4px 12px rgba(74, 144, 226, 0.15)`

選択変更時は、青枠と背景色も新しい選択先へ移動する。

CSSはcontainer key由来のクラスを対象とし、`nth-child`などDOMの出現順に依存する指定は使用しない。

Plotlyチャートの固定幅・固定高はCSSで変更せず、カードの背景・枠・余白だけを調整する。

## 6. 問題画面の配色

問題画面だけ、ページ背景を次の色へ変更する。

```text
#F6F8FB
```

CSSは`current_view == "question"`の分岐内だけで出力する。

結果画面では問題画面用CSSを出力しない。

結果画面の背景、Reviewチャート、ボタン、配色はTask012までの表示を維持する。

## 7. 回答ボタン

- 「回答する」ボタンは問題画面下部に1つだけ表示する。
- 各チャート下の旧選択ボタンは表示しない。
- 既存の回答ボタンkeyである`submit_answer`を維持する。
- 回答ボタン用CSSは`submit_answer`だけを対象とし、Chart選択ボタンへ適用しない。
- 主ボタンとして青系で表示する。
- ボタン背景色：`#2F6FB2`
- 文字色：`#FFFFFF`
- 角丸：`10px`
- 選択UIとの間に十分な余白を設ける。
- ライトテーマで通常サイズ文字の可読性を確保する。

未選択のまま押した場合は、既存どおり次の警告を表示する。

```text
1つ選択してください。
```

## 8. Session Stateとwidget key

アプリ状態として使用するSession Stateは既存の5つだけとする。

- `game_question`
- `answer_choice`
- `selected_label`
- `submitted`
- `current_view`

新しいアプリ状態用Session Stateキーは追加しない。

Streamlit widgetの識別に必要な一意のkeyは使用してよい。

使用するwidget keyは次とする。

- `select_chart_a`
- `select_chart_b`
- `select_chart_c`
- `submit_answer`

`st.button()`は押下イベントだけを返し、選択状態は`answer_choice`から毎回描画する。

widget keyを選択状態の判定へ使用しない。

widget側に独立した選択状態を保持しないため、次問題で`answer_choice=None`へ戻るとUIも未選択状態へ戻る。

## 9. 状態別の挙動

### 未選択

- `answer_choice=None`
- A/B/Cすべて`○`
- A/B/Cすべて未選択カード配色
- 回答ボタン押下時は警告を表示

### Chart選択中

- `answer_choice`へ選択ラベルを保存
- 選択中Chartだけ`●`
- 選択中カードだけ青枠・薄い青背景
- 未選択Chartは`○`とグレー枠
- 選び直し可能
- 選択操作で更新するアプリ状態は`answer_choice`だけ

### 回答確定

既存どおり次を一括更新する。

- `selected_label = answer_choice`
- `submitted = True`
- `current_view = "result"`

更新後に`st.rerun()`を1回だけ呼ぶ。

正誤判定、結果画面、二重回答防止は変更しない。

### 次の問題

既存どおり次へ戻る。

- `answer_choice=None`
- `selected_label=None`
- `submitted=False`
- `current_view="question"`

A/B/Cはすべて未選択表示へ戻る。
