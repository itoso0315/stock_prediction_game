# Task 017

## 1. Task名

結果画面へのテクニカルひとこと解説追加

## 2. 目的

現在のStock Trainerでは、利用者は問題へ回答した後に、正解・不正解、企業名、証券コード、将来騰落率、Reviewチャートを確認できる。

一方で、なぜそのChartが正解になったのか、どのようなテクニカル要素に注目すべきだったのかは説明されない。

Task017では、1問ごとの結果画面へ、チャート形状とテクニカル指標だけを根拠にした短い解説を追加する。

利用者が「当たった・外れた」で終わらず、次の問題へ判断基準を持ち越せるようにすることが目的である。

## 3. 基本方針

Task017では外部の生成AI APIを使用しない。

Pythonで価格・出来高・移動平均線の特徴を計算し、あらかじめ定義したルールから解説文を生成する。

画面上の表示名は、将来の生成AI連携を見据えて次とする。

```text
AIひとこと解説
```

ただし、Task017の実体はルールベースのテクニカル解説である。

利用者画面では誤認防止のため、見出し直下に次の補足を小さく表示する。

```text
価格・出来高・移動平均線から自動生成したルールベース解説です。
```

## 4. 設計思想

解説は次の方針を守る。

- テクニカル分析だけを扱う
- 問題画面では表示しない
- 回答確定後の結果画面だけで表示する
- 将来騰落率そのものを理由として説明しない
- 企業名やニュースを根拠にしない
- 正解を後付けで断定的に正当化しない
- 初心者が次回使える観点を1つ伝える
- 投資助言や売買推奨として表現しない

## 5. 今回の実装対象

Task017で実装する内容は次のとおり。

- 各Chartの観察期間データからテクニカル特徴を抽出
- 正解Chartまたは現金正解の理由候補を生成
- 利用者が不正解の場合は、選択Chartとの違いを補足
- 結果画面へ短い解説カードを1件表示
- 正解時・不正解時・現金正解時の文面分岐
- 解説生成失敗時の安全なフォールバック
- Task016までの10問チャレンジ、企業情報、移動平均線表示を維持

## 6. 今回の対象外

次はTask017では実装しない。

- OpenAI APIなど外部生成AIの利用
- 自然言語モデルによる自由生成
- ニュース分析
- 決算分析
- PER、PBR、配当利回り
- 業種比較
- 企業研究
- 将来株価の予測
- 売買推奨
- AI解説の履歴保存
- 解説のスコアリング
- 解説へのユーザー評価
- 難易度別解説
- RSI、MACD、一目均衡表
- 自動テストファイルの新規作成

## 7. 使用するデータ

解説生成には、各`ChartQuestion`が保持する観察期間の`display_data`だけを使用する。

使用可能な列は次のとおり。

- `Open`
- `High`
- `Low`
- `Close`
- `Volume`

問題画面では引き続き将来情報を表示しない。

結果画面で解説を生成する場合も、解説の根拠計算には`future_data`を使用しない。

`future_data`は正解判定とReviewチャート表示の既存処理だけで使用する。

## 8. 使用するテクニカル特徴

Task017では次の特徴を計算対象とする。

### 8.1 移動平均線

- MA25
- MA50
- MA75

計算式：

```python
close.rolling(window=N, min_periods=N).mean()
```

解説判定には、十分な期間が存在する末尾の有効値だけを使用する。

画面表示用の`min_periods=1`とは分離する。

### 8.2 株価と移動平均線の位置

観察期間最終日の終値について、次を判定する。

- 終値がMA25より上か
- 終値がMA50より上か
- 終値がMA75より上か

終値と移動平均線が同値の場合は「上ではない」と判定し、各`close_above_maXX`へ`False`を設定する。同値専用の状態は追加しない。

### 8.3 移動平均線の並び

観察期間最終日時点で次を判定する。

上昇型：

```text
MA25 > MA50 > MA75
```

下降型：

```text
MA25 < MA50 < MA75
```

それ以外は混在型とする。

### 8.4 移動平均線の傾き

各移動平均線について、最新の有効値を`iloc[-1]`、5営業日前の有効値を`iloc[-6]`として比較する。

上向き：

```text
current_ma > previous_ma
```

下向き：

```text
current_ma < previous_ma
```

同値は横ばいとする。

MA75の最新値と5営業日前の有効値を得るため、入力データは最低80営業日必要とする。

### 8.5 高値・安値の切り上げ、切り下げ

直近20営業日を前半10日と後半10日に分ける。

次を比較する。

- 前半の最高値と後半の最高値
- 前半の最安値と後半の最安値

高値・安値の両方が厳密に上昇した場合だけ`higher`、両方が厳密に低下した場合だけ`lower`とする。片方だけ変化した場合、または一方でも同値の場合は`mixed`とする。

### 8.6 出来高の変化

直近20営業日を前半10日と後半10日に分け、平均出来高を比較する。

後半平均が前半平均の1.2倍以上：

```text
出来高が増加している
```

後半平均が前半平均の0.8倍以下：

```text
出来高が減少している
```

それ以外は横ばいとする。

前半10営業日の平均出来高が0の場合は、後半平均も0なら`flat`、後半平均が正なら`up`とする。負の出来高は不正値として`ValueError`を送出する。

## 9. 特徴抽出結果

Chartごとに、次の情報を持つ辞書を生成する。

```python
{
    "close_above_ma25": bool,
    "close_above_ma50": bool,
    "close_above_ma75": bool,
    "ma_alignment": "bullish" | "bearish" | "mixed",
    "ma25_slope": "up" | "down" | "flat",
    "ma50_slope": "up" | "down" | "flat",
    "ma75_slope": "up" | "down" | "flat",
    "price_structure": "higher" | "lower" | "mixed",
    "volume_trend": "up" | "down" | "flat",
}
```

返却辞書は上記9キーだけを持つ。値はPython組み込みの`bool`または`str`へ変換し、NumPy固有の真偽値は返さない。

新しいデータクラスは作成しない。

## 10. 解説生成ルール

正解Chartの解説には、優先順位が最も高い特徴を1件だけ使用する。

不正解時のみ、正解Chartの強み1件に加えて、選択Chartの注意点を最大1件追加できる。この場合だけ最大2文とする。

優先順位は次のとおり。

1. 強い上昇型：`ma_alignment == "bullish"`かつMA25・MA50・MA75がすべて`up`
2. 3本の移動平均線がすべて上向き
3. 高値・安値の切り上げ：`price_structure == "higher"`
4. 株価が上向きのMA75より上
5. 出来高増加：`volume_trend == "up"`
6. 固定フォールバック文

複数条件を同時に満たす場合は、上記順で最初に該当した1件だけを採用する。

## 11. 正解Chartの解説

正解がChart A/B/Cの場合、正解Chartの特徴から解説を生成する。

### 11.1 強い上昇型

条件：

```text
MA25 > MA50 > MA75
かつ
MA25・MA50・MA75がすべて上向き
```

表示例：

```text
正解のChart Bは、MA25・MA50・MA75が上向きの順行で、上昇トレンドが比較的明確でした。
```

### 11.2 3本の移動平均線がすべて上向き

条件：

```text
ma25_slope == "up"
かつ
ma50_slope == "up"
かつ
ma75_slope == "up"
```

表示例：

```text
正解のChart Bは、MA25・MA50・MA75がすべて上向きで、上昇方向への流れがそろっていました。
```

### 11.3 高値・安値の切り上げ

条件：

```text
price_structure == "higher"
```

表示例：

```text
正解のChart Aは、直近で高値と安値を切り上げており、買いの流れが続いていました。
```

### 11.4 株価が長期線より上

条件：

```text
close_above_ma75 is True
かつ
ma75_slope == "up"
```

表示例：

```text
正解のChart Cは、株価が上向きのMA75より上にあり、中長期の上昇基調を維持していました。
```

### 11.5 出来高増加

条件：

```text
volume_trend == "up"
```

表示例：

```text
正解のChart Aは、直近で出来高が増えており、値動きの勢いが強まっていました。
```

### 11.6 明確な特徴がない場合

```text
正解のChart Bは、今回使用した指標だけでは明確な特徴を1つに絞れませんでした。
```

## 12. 不正解時の補足

注意点の優先順位と固定テンプレート：

1. `ma_alignment == "bearish"`

   ```text
   一方、選択したChart Aは移動平均線が下降型で、下向きの流れが強い形でした。
   ```

2. `ma75_slope == "down"`

   ```text
   一方、選択したChart AはMA75が下向きで、中長期の流れが弱い形でした。
   ```

3. `price_structure == "lower"`

   ```text
   一方、選択したChart Aは高値と安値を切り下げており、下落基調が続いていました。
   ```

4. `close_above_ma75 is False`

   ```text
   一方、選択したChart Aは株価がMA75を上回っておらず、中長期では弱い位置でした。
   ```

5. `volume_trend == "down"`

   ```text
   一方、選択したChart Aは出来高が減少しており、値動きの勢いが弱まっていました。
   ```

`close_above_ma75 is False`は「MA75より下」ではなく「MA75を上回っていない」と表現する。同値も含むため、「下回る」「下にある」とは表現しない。

複数候補がある場合は、上記順で最初の1件だけを使用する。表示時は`Chart A`を実際の選択ラベルへ置き換える。

選択Chartに明確な弱点がない場合は、比較文を追加しない。

## 13. 現金正解時の解説

次の条件と固定テンプレートを優先する。

1. 3Chartのうち2件以上が下降型

   ```text
   今回は3つのChartの多くが移動平均線の下降型だったため、現金で見送る判断が有効でした。
   ```

2. 3Chartのうち2件以上でMA75が下向き

   ```text
   今回は3つのChartの多くでMA75が下向きだったため、現金で見送る判断が有効でした。
   ```

3. 3Chartのうち2件以上で高値・安値を切り下げ

   ```text
   今回は3つのChartの多くが高値と安値を切り下げていたため、現金で見送る判断が有効でした。
   ```

4. 3Chartのうち2件以上で株価がMA75を上回っていない

   ```text
   今回は3つのChartの多くがMA75を上回っておらず、現金で見送る判断が有効でした。
   ```

`close_above_ma75 is False`は同値を含むため、条件4では「MA75より下」ではなく「MA75を上回っていない」と表現する。

複数条件を満たす場合は、上から最初に該当した1件だけを使用する。

4条件のどれにも該当しない場合は、次の固定文を使用する。

```text
今回は3つのChartに明確な上昇優位性が見られず、現金で見送る判断が最も良い結果でした。
```

現金正解時も、将来騰落率の数値を解説根拠として表示しない。

## 14. 現金を選んで不正解だった場合

利用者が現金を選び、正解がChart A/B/Cだった場合は、正解Chartの強みだけを表示する。

表示例：

```text
正解のChart Cは、MA25・MA50・MA75が上向きで、上昇方向への流れが比較的明確でした。
```

現金選択を否定的・感情的に表現しない。

## 15. 表示文の長さ

解説本文は原則として次を満たす。

- 正解時・現金正解時・現金選択不正解時は1文
- Chartを選んで不正解だった場合だけ最大2文
- 本文は120文字以内を必須とする
- 文字数には見出しを含めず、Pythonの`len()`で数える
- 120文字を超える場合は、選択Chartの補足文を省略して正解Chartの1文だけを表示する
- 箇条書きにしない
- 専門用語を使いすぎない
- 断定しすぎない

許容表現：

- 比較的明確でした
- 上昇基調を維持していました
- 勢いが強まっていました
- 相対的に底堅い形でした

禁止表現：

- 必ず上がる
- 買うべき
- 売るべき
- 絶対に正解
- 確実な上昇

## 20. エラー処理

次の不正状態はフォールバック対象にせず、`ValueError`を送出する。処理先は次のとおり固定する。

### 20.1 Session State正規化へ委ねる状態

- `selected_label`が許容値外
- `selected_label is None`

上記は既存のSession State正規化を適用し、結果画面を表示しない。

### 20.2 結果画面エラーとして扱う状態

- `question.charts`が3件ではない
- Chartラベルが`Chart A`、`Chart B`、`Chart C`の順で一意ではない
- `correct_label`が許容値外

上記は既存の結果画面エラー処理へ渡し、結果・解説・次の操作ボタンを部分表示しない。

テクニカル特徴抽出または文面選択だけに失敗した場合は、結果画面全体を非表示にせず、次の固定フォールバック文へ置き換える。

```text
今回は明確なテクニカル特徴を1つに絞れませんでした。複数の指標を組み合わせて確認してみましょう。
```

3Chart中1件でも特徴抽出に失敗した場合は、残りのChartだけで解説を生成せず、解説全体を上記フォールバック文へ置き換える。

解説生成失敗は、Review Figure生成失敗とは分離する。

- Review Figure生成失敗：既存どおり結果画面全体を部分表示しない
- 解説生成失敗：フォールバック文を表示して結果画面を続行

結果画面では、先にReview Figure・企業情報・URL・比較情報を含む既存表示情報を準備し、その後に解説文を確定する。いずれかの既存表示情報準備に失敗した場合は、解説カードを含めて何も部分表示しない。

利用者画面へ例外詳細、ticker、内部データを表示しない。

## 25. 入力検証

`extract_technical_features()`は次を検証する。

- `prices`が`pandas.DataFrame`
- 空でない
- `High`、`Low`、`Close`、`Volume`列が存在
- 80営業日以上存在
- インデックスが`DatetimeIndex`
- インデックスに`NaT`がない
- インデックスが昇順
- インデックスに重複がない
- 入力順を自動で並べ替えない
- 対象列は数値型であり、数値文字列は拒否する
- 対象列に`NaN`、`inf`、`-inf`がない
- `Volume`に負の値がない

条件を満たさない場合は`ValueError`を送出する。

入力DataFrameは変更しない。特徴抽出はコピーまたは読み取り専用操作で行う。

`generate_technical_comment()`は次を検証する。

- `question`が`GameQuestion`
- `question.charts`が3件
- Chartラベルが`Chart A`、`Chart B`、`Chart C`の順で一意
- `selected_label`がChart A/B/Cまたは`CASH_OPTION_LABEL`
- `correct_label`がChart A/B/Cまたは`CASH_OPTION_LABEL`
- `selected_label is not None`
